## 3. 已落地配置

用户已确认外部晶振为 **8 MHz**。HSE 使用 Crystal/Ceramic Resonator，PLL ×9：

- SYSCLK、HCLK、APB2：72 MHz；APB1：36 MHz。
- TIM1/2/3 输入时钟：72 MHz；SysTick：1 ms。
- Flash：2 wait states；调试：Serial Wire，PA13/PA14。
- USART1：PA9/PA10，115200、8N1，调试日志。
- USART2：PA2/PA3，115200、8N1，ESP-01S 预留。模块实际 AT 波特率后续核对。
- USART3：PB10/PB11，9600、8N1，SU-03T 沿用旧参数，随实际语音固件核对。
- I2C1：PB6/PB7，100 kHz，7 位地址；OLED 型号和地址待实物确认。
- TIM3_CH1：PA6，PSC=71、ARR=999，1 kHz PWM，初始比较值 0。
- TIM1_CH1：PA8，PSC=71、ARR=999，1 kHz 预留 PWM，初始比较值 0；PA7 为普通推挽输出，初始低电平。风扇最终频率和极性由 R04 实测确定。
- TIM2：PSC=71、ARR=65535，1 MHz 自由计数，在启动代码中启用；每 65.536 ms 回绕，后续微秒差值应采用 16 位无符号差处理。
- PB0：DHT11 双边沿 EXTI 引脚预留，GPIO 无内部上下拉；外接 4.7 kΩ 上拉至 3.3 V。当前未启用 EXTI0 NVIC，也未接收 DHT11 数据，R02 实现驱动时启用。
- PB12/13/14：上拉输入，低有效，对应 LED、风扇开关、风速按键。

TIM1/TIM3 的 PWM 输出均未启动。TIM1 没有启用互补输出或 Break 输入，USART 没有流控、同步时钟或重映射。

## 4. 启动行为与代码维护

生成的 `main.c` 先完成 HAL、时钟和各外设初始化，然后检查时钟配置、启动 TIM2，并通过 USART1 输出启动信息。此后每秒输出一次 `[R01] alive`。

Keil Watch 可观察：

- `g_r01_heartbeat`：每秒递增。
- `g_r01_uart_errors`：串口发送失败计数，正常为 0。
- `uwTick`、`SystemCoreClock` 和 `TIM2->CNT`：辅助验证系统时基和计数器。

日志直接调用 `HAL_UART_Transmit`，没有使用 `printf` 或半主机。硬件初始化失败进入 CubeMX 的 `Error_Handler`，可在此设置断点定位。

新增启动代码全部位于 `USER CODE BEGIN/END` 区域。修改硬件配置时打开 `.ioc`、Generate Code，再打开 `.uvprojx` 重编译。后续驱动、业务代码放入各自源文件，并加入 Keil 工程；生成代码区域继续由 CubeMX 管理。

## 5. 编译方法与记录

打开 `firmware/SmartHomeDemo/MDK-ARM/SmartHomeDemo.uvprojx`，选择 `SmartHomeDemo` 目标，执行 Rebuild。也可从仓库目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

脚本使用 Keil 官方 `UV4 -r` 接口全量重编译，检查进程退出码、零错误零警告摘要以及 HEX 文件。参见 [Keil 命令行说明](https://www.keil.com/support/man/docs/uv4/uv4_commandline.asp)。本次编译在正常 Windows 执行环境完成；受限沙箱可能阻止旧版 ARM 32 位工具运行。

- 编译结果：0 Error(s), 0 Warning(s)。
- Code=6664，RO-data=468，RW-data=28，ZI-data=3172 字节。
- Flash 使用约 7160 字节；RAM 使用约 3200 字节（含 0x800 栈、0x200 堆）。
- 输出：`firmware/SmartHomeDemo/MDK-ARM/SmartHomeDemo/SmartHomeDemo.hex` 和 `.axf`。
- 本地完整日志：`artifacts/keil-build.log`。
- 源码配置已检查：HSE=8 MHz、PLL ×9、FLASH_LATENCY_2、SWD、外设引脚及独立 PWM 分配。
- CubeMX 再生成检查通过：包含用户启动代码的 `main.c` 再生成前后 SHA-256 一致。

## 6. 接板后验收

以下步骤尚未执行，不能据编译通过报告“已经上板运行”。

1. 将 ST-Link 的 SWDIO/SWCLK/GND 接至主控板 PA13/PA14/GND，按实际板卡方式供电。在 Keil 的 Debug Settings 中确认 ST-Link 和 SW 接口，确认能识别目标。
2. 检查 Flash Download 算法与 STM32F103C8 的 64 KB 地址范围相符，再下载 HEX/AXF。
3. USB-TTL 使用 3.3 V 信号，RX 接 PA9，GND 共地；设置 115200、8N1。复位后应出现启动信息，之后每秒出现 `[R01] alive`。
4. 检查 `SystemCoreClock=72000000`、心跳计数递增、TIM2 持续计数、串口错误计数为 0。核对复位后可重复启动。
5. 将实际结果补充到 `develop` 的验证记录；实机验收通过后，再将该版本认定为后续模块的绿色基线。

首次工程验证只需要主控板、ST-Link 与调试串口。HS-F04P 的 5 V 输入适配仍按引脚文档待处理；当前没有用 R01 固件进行负载联调。

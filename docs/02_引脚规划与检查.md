# 引脚规划与检查

版本：v1.0

主控：STM32F103C8T6  
状态：原理图 GPIO 与外设分配静态检查通过；R01 已生成 CubeMX/Keil 工程并通过编译，接口适配和实物验证待完成。

## 1. 检查范围与结论

检查对象为 [用户提供的项目原理图](../SCH_Schematic1_2026-10-24.pdf)，并结合用户确认的 ESP-01S、SU-03T、HS-F04P、0.96 寸 I²C OLED 和新增 DHT11 需求。

**结论：现有信号引脚可以保留，新增 DHT11 DATA 使用 PB0。采用 LED 的 TIM3_CH1、风扇的 TIM1_CH1 加普通 GPIO 的方案后，没有引脚重复占用或必须改线的外设资源冲突。**

初次检查针对原理图分配及计划中的外设模式。随后 R01 已按本表生成 `.ioc` 和 Keil 工程并编译通过，具体配置与验证记录见 [R01 工程说明](03_R01_工程说明.md)。HS-F04P 输入接口有尚需处理的电平适配问题，见第 6 节；本结论不代表原理图所有电气连接均已通过。

U2 是带电源和排针编号的主控板符号，图中 1～40 的编号不是 STM32 裸芯片封装脚号。CubeMX 按 PAx/PBx 名称配置，实物按主控板丝印寻找对应引脚。

## 3. DHT11 新增接线

选择 PB0 的理由：原理图中空闲、主控板已引出、无需调整其他模块；使用 GPIO 时不会占用 UART 或 I²C，也无需使用 TIM3_CH3 的复用功能。

| DHT11 信号 | 接线 |
| --- | --- |
| VDD/VCC | 3.3V |
| DATA | PB0，网络名建议 DHT11_DATA |
| GND | 系统 GND |
| NC | 裸四脚器件的空脚不连接 |

DATA 用约 4.7 kΩ 电阻上拉到 3.3V。若购买的是带电路板的三针模块，按模块丝印接线并核实已有上拉，不能套用裸四脚器件的编号或重复盲加电阻。使用短连线。

原理图 U2 的 PB0 位于该符号第 33 脚，应移除其未连接标记，补充 DATA 网络、供电、地和上拉；本轮只提供补图要求，未修改原 PDF。

CubeMX 规划为 PB0 的 GPIO/EXTI0 接收模式，发送起始信号时由驱动临时切换为开漏输出并拉低，随后释放总线切回输入接收。不得同时启用 PB0 的 ADC 或 TIM3_CH3 输出。EXTI0 只分配给 PB0，按键使用轮询消抖。

建议 TIM2 使用内部时钟提供微秒计时，不启用外部通道。发送起始信号及接收时序由 DHT11 驱动完成，不把生成的 GPIO 初始化当作驱动本身。

本项目定为上电约 2 秒后首次读取、之后每 3 秒读取一次。供电、上拉及采样间隔依据奥松 DHT11 V1.3 手册；具体裸器件/模块脚序仍以实物标识为准。

## 4. PWM 与资源使用

| 资源 | 本项目用途 | 配置边界 |
| --- | --- | --- |
| TIM3_CH1 / PA6 | LED PWM | 只启用 CH1；初始候选 1 kHz，亮度修改比较值 |
| TIM1_CH1 / PA8 | 风扇 PWM | 只启用 CH1；频率、极性和三档占空比由风扇模块实测确定 |
| PA7 GPIO | 风扇另一输入 | 维持选定方向所需的固定电平；停止组合随实际接口极性确定 |
| TIM2 内部计数 | DHT11 微秒计时 | 不启用外部时钟、输入输出通道或引脚重映射 |
| I2C1 / PB6、PB7 | OLED | 使用默认引脚；总线速率初始候选 100 kHz |
| USART1 / 2 / 3 | 调试 / Wi-Fi / 语音 | 均使用异步模式，无硬件流控 |
| SysTick | 系统毫秒时基 | 用于周期任务及按键等时间判断 |

PA7 虽可复用为 TIM3_CH2，本方案将其保留为普通 GPIO。这样风扇调速由 TIM1 控制，LED 调光由 TIM3 控制，两者能够独立确定 PWM 频率。

固定方向风扇无需两路不同定时器的 PWM。具体运行电平及停止组合须连同 HS-F04P 接口一起验证；如需要改变机械转向，可在确认接线后调整电机两端的对应关系，不在本版增加反转业务。

避免误启用以下复用功能：

- TIM1_CH1N/CH2N 和 Break 输入：会涉及 PB13/PB14/PB12，已用于按键。
- USART3 硬件流控、同步时钟：会涉及按键引脚，本项目均不需要。
- USART1 重映射到 PB6/PB7：这两个引脚已分配给 OLED。
- USART1 同步时钟或 MCO：会占用 PA8，已分配给风扇 PWM。
- TIM3_CH2/CH3、SPI1、I2C2：不能覆盖 PA7、PB0 或语音串口的已定用途。

模块接收方式、DMA 通道及中断优先级在后续模块设计中确定。当前没有 `.ioc`，不宣称 DMA/中断配置已经检查通过。

## 5. CubeMX 配置落地要求

- 选择实际 STM32F103C8T6，生成 HAL 工程，目标工具链选择适配本机 Keil5 的 MDK-ARM。
- SYS Debug 使用 Serial Wire，并从主控板实际 SWD 排针接入下载器。图中的 U6 是串口接口，不能代替 Keil 的 SWD 下载调试连接。
- 三路 UART 的 TX/RX 按第 2 节分配。语音初始规划 9600、8N1；Wi-Fi 和调试初始规划 115200、8N1，Wi-Fi 参数必须与实物 AT 固件一致。
- OLED 的 PB6/PB7 使用 I²C 开漏复用方式，上拉按模块实际电路处理。
- PB12/PB13/PB14 使用输入上拉，按下读低电平；软件完成正常按键消抖。
- PA7 作为普通输出；风扇输出的初始电平、PWM 极性和停止状态根据接口适配结果确定。
- 用户已于 R01 阶段确认板载外部晶振为 8 MHz；实际工程使用 HSE ×9，SYSCLK 为 72 MHz，等待接板验证。
- 保留用户代码区域，驱动与业务源文件单独组织。完成配置后检查引脚视图、时钟树和生成工程，再在 Keil5 中编译验证。

这些要求已在 R01 工程中落地；PB0 的 EXTI0 NVIC 待 R02 驱动实现时启用，实物验证另行记录。

## 6. 原理图及接口待落实项

### 6.1 HS-F04P 接口脚序

当前项目 H2 与现有 HS-F04P Rev 1.0 原理图的 CN1 脚序相反。按信号名连接，不能假定相同编号直通：

| 项目 H2 | 信号 | HS-F04P CN1 |
| --- | --- | --- |
| 1 | IN-B | 4 |
| 2 | IN-A | 3 |
| 3 | 5V/VCC | 2 |
| 4 | GND | 1 |

这是根据两张图得到的端子对应关系；实物连接器朝向、线束编号和风扇额定供电仍需核对。

### 6.2 HS-F04P 输入适配

现有 HS-F04P Rev 1.0 图纸显示 IN-A、IN-B 各经 10 kΩ 上拉至模块 VCC，且两个输入之间有 100 nF 电容。项目 H2 给驱动板提供 5V，而 PA7 在 STM32 数据手册中不是 FT（5V 容忍）引脚。

因此，**当前 5V 驱动板输入与 PA7 直接连接的电平兼容性未通过，不能把引脚分配通过写成直连接线通过**。保留 PA8/PA7 的分配，后续确定适配 3.3V MCU 与驱动输入侧的缓冲或电平转换接口，并核对实际极性和波形。具体接口元件和接法需要根据实物板确认，不在此文中虚构已经完成的电路修改。

输入电容也意味着不能直接承诺某一 PWM 频率一定适用。驱动模块验证阶段应确定可用频率、停止组合及低中高档参数；如实物版本没有上述上拉或电容，以核对后的实物记录修订此项。
